# 个人主页与 builder 作品集参考

调研日期：2026-11-11。直接阅读 8 个作者官网及作品子页；以下“共性”是对这批样本的设计判断，未经转化率实验验证。重点研究内容组织和可信度，不能仅凭文字抓取判断完整视觉、动效或移动端体验。

## 这批样本的有效共性

1. **先回答做什么，再让作品说话。** Paco、Anthony、Shu 的首页都很快进入具体产物；介绍里有领域和工作对象，而不是只有“有想法就做”。
2. **长尾与重点分层。** Anthony 的 Current Focus/完整分类，Shu 的主要贡献/小实验，Paco 的首页/Craft 子页，都允许快速浏览和深入阅读共存。
3. **项目是入口。** 好的条目让读者能直接进入产品、代码、文章或演示，读完一句话就能继续验证。
4. **具体贡献比自评有用。** Shu 解释设计、实现了哪些部分；Anthony 区分角色。对本页而言，原生项目、fork 改进、研究、尚未跑通的原型要说清楚。
5. **有个性，但个性来自真实内容。** 兴趣、实际使用场景、选题、交互细节，比写一套“我信什么”的口号更自然。
6. **视觉要服务证据。** Bruno 的交互是技能样本，Paco 的实验能继续点开，Josh 的教程是主内容。没有所有人通用的一套卡片或大标题模板。

## 应用到 Yiju 这一版

建议方向：一个简洁、能继续探索的个人作品集。保留架构图的统一画法，把它们放在具体项目里；首屏取消“我→四台机器→看板→21 个项目”的自我生产流水线图。它解释了内部流程，却没有让第一次来的读者理解产物价值。

- **首屏**：姓名 + 一句具体介绍，例如“我做 AI agent 工具，也做一些日常会用的软件。”随后直接接作品。可保留一个低调的 builder 标识；不用把“我是一个 builder”放到最大字号。
- **重点作品候选**：agent-pm、Noteweaver、cangjie-skill。三者都有仓库入口，能体现 agent 协作、知识管理、评测三个不同问题。是否公开、实际贡献及状态仍以仓库和现有事实为准。
- **每个重点项目**：名称；一至两句“是什么/给谁用”；一条具体实现或贡献；仓库/演示链接；展开架构。不要机械重复“为什么造 / 我的判断 / 现在”三栏。技术信息应该帮助理解作品，不必每项都写成自我评价。
- **原型与研究**：openlingo、rsi-quant 等保留准确状态；可以用小卡片/短行，避免与已在用的工具混成同一种完成度。没有跑通就直说“原型”，不用“还差最后一步”制造完成暗示。
- **其余开源**：名称、用途、链接即可。已知有 ConferenceFlow 的演示地址，可核验后提供 Try/Open 类直接入口。
- **About**：两三句现有事实和兴趣即可。学位、工作经历、地区、客户、用户数、收入都不能从项目看板推断。
- **联系**：使用已有 GitHub；没有提供的邮箱和社交账号不要虚构。

## 素材与真实性边界

现有项目数据来自本仓库 `build.mjs`；这一轮没有验证每个项目代码、发布版本或 README。优先使用已有真实素材。若没有产品截图，保持干净排版与真实架构图，比画一个看似已发布的 dashboard 更可信。可以做明确标注为“交互说明”的小型可操作组件，但不得冒充真实界面、活跃任务数、用户数或收益。

不建议照搬：Bruno 的 3D 世界、名企履历墙、无依据的增长数字、纯装饰的终端输出、几十个同权重卡片，以及“builder”身份宣言式文案。上面这些选择是对本案信息资产和表达目的的判断，并不是否定原作者的形式。

## 本轮实际采用的方案

首页落为姓名、一句具体介绍和低调的 Builder 标识；以排版、细线和单一蓝色组织内容。移除首屏的个人生产流水线、项目数量口号、四条方法宣言，以及推测出的私人动机。

精选实际使用与实现内容各不相同的三个工具：herdr-pm（原看板名 agent-pm）、Noteweaver、Herdeo。首层写用途与结果，直接提供源码入口；实现细节和原有风格的架构图按需展开。cangjie-skill、openlingo、rsi-quant 单列实验与研究，明确 fork、原型、模拟盘的角色与状态。其余公开仓保持短索引，其他看板项目收在可展开的记录中；沿用上一版隐藏的五项私人事务。

内容已对照本地 `../herdr-pm/README.md`、`../noteweaver/README.md`、`../herdeo/README.md`。核对各仓库的 origin 后，把错误的 `yiju-zhao/agent-pm` 源码链接更正为 [yiju-zhao/herdr-pm](https://github.com/yiju-zhao/herdr-pm)。另外两个入口为 [Noteweaver](https://github.com/yiju-zhao/noteweaver) 和 [Herdeo](https://github.com/yiju-zhao/Herdeo)。本轮未逐一验证所有公共仓库的在线访问状态。

验证范围：生成脚本语法与构建、HTML ID/锚点/资源引用、CSS 变量、标题结构及全部架构图生成。当前环境不能绑定本地 HTTP 端口；独立浏览器接口不可用，连接现有 Safari 的请求被自动审核拒绝。尚未完成实际页面的桌面、手机渲染与交互验收。
